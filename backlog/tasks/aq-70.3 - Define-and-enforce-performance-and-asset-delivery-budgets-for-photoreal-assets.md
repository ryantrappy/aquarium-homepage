## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Photorealism raises texture resolution, geometry density and shading cost. Without explicit budgets, higher-fidelity assets will either make the homepage slow to load or drop frames, especially on the iPhone-class proxy viewport. Budgets must exist before the renderer and asset upgrades land so each task can prove it fits.

Areas to cover:
- Download budget (initial and total), GPU texture memory budget, per-asset-class triangle and texture-size caps (hero fish, background fish, coral colony, rock island, sand).
- Texture delivery: KTX2/Basis Universal (three KTX2Loader) for color and data maps; geometry compression (meshopt or Draco, for example via glTF-Transform, MIT); LODs where justified.
- Frame-time budgets at 1440x900 and 402x874 with the maximum supported fish count, and an automatic quality-tier fallback (pixel ratio, shadow map size, post-processing passes) when measured frame time exceeds budget.
- Load order: show a fully composed scene progressively without layout shifts; keep fish links usable while high-resolution textures stream.
- Extend the existing asset manifest checker (src/rendering/assets, AQ-42.1 manifest hashes) so budgets are validated automatically in npm test.

Responsive verification uses only 1440x900 (laptop) and 402x874 CSS pixels at scale 1 (iPhone 18 Pro proxy); do not add a broader device matrix.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
