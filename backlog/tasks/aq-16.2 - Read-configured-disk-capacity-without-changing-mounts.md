## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The reviewed AQ16.1 math needs actual filesystem readings. Implement a small trusted-source adapter under src/server/disk-capacity.ts and its direct test only. A configured source supplies a stable selection ID, label and explicit absolute directory on an eligible data/root filesystem; the client never supplies paths. Read Node stat/statfs with bigint values, dedupe filesystem identities before sampling capacity, and feed the reviewed math. No API/UI/environment or Compose/host/mount changes in this packet. No broad host filesystem discovery. Server configuration remains responsible for intended mounted data scopes; do not pretend a container overlay is a host disk.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Confirm AQ-16.1’s bigint aggregation contract and Node fs/statfs behavior; keep the public surface limited to trusted {id,label,directory} sources, getSources(), and read(sourceId | 'all').
2. Use injected bigint stat/statfs readers plus wall and monotonic clocks. Validate absolute configured directories and directory stats, group by stat.dev before one statfs sample per unique filesystem, validate block readings, and feed exact bsize*blocks/bavail bytes into aggregateDiskCapacity.
3. Make a selected read atomic. For all-scope, any configured-source/stat/statfs/validation failure invalidates the entire new aggregate; return only a prior coherent result as stale, with stored observedAt and elapsed age from the monotonic clock. Unknown IDs/scopes and no prior good data are explicitly unavailable.
4. Reject virtual/overlay filesystems based on verified platform semantics. Proposed safe boundary pending Root review: Linux-only recognized persistent-filesystem allowlist for statfs.type; on non-Linux, return unavailable because Node exposes only a numeric type and the Darwin value is not safely classifiable from Node’s API. Validate the real temporary-directory statfs path where supported.
5. Add only src/server/disk-capacity.ts and src/server/disk-capacity.test.ts, run focused tests/typecheck and report evidence. No API, configuration, host discovery, or mount changes.

Root review correction (2026-11-04): exclude btrfs from the supported-filesystem allowlist because independently mounted subvolumes share one Btrfs storage pool, while the adapter has no safe fsid/subvolume-aware identity source; `stat.dev` alone must not be assumed to represent the capacity-accounting filesystem for every Btrfs subvolume mount. Keep ext/xfs unchanged and add a regression that Btrfs magic remains unavailable. Primary references: Btrfs docs describe subvolumes as separately mountable roots that share the single filesystem storage pool (https://btrfs.readthedocs.io/en/latest/Subvolumes.html); Linux proc mountinfo documentation defines its major:minor device field as `st_dev` (https://docs.kernel.org/filesystems/proc.html#proc-pid-mountinfo-information-about-mounts).

Review the in-flight promise map for cloned results, coherent per-scope stale caches and duplicate-read behavior; change only if an observable correctness issue is found. Re-run focused tests/typecheck and leave status In Progress for Root.

The adapter validates only trusted absolute source directories; exposes getSources/read only; groups source aliases by bigint stat.dev before statfs; computes bsize*blocks and bsize*bavail exactly; and routes unique filesystem records through AQ-16.1 weighted aggregation. Any all-scope source failure returns unavailable or the previous whole aggregate as stale, aged with performance.now rather than wall-clock time.

Those host values are deliberately not interpreted as Linux or exposed as a host-disk reading. The real temp-directory smoke verified bigint stat/statfs shape and the adapter's explicit non-Linux unavailable path. No Linux server filesystem was available for a positive real-filesystem smoke; Linux filesystem behavior is covered with deterministic injected readers (ext/xfs/btrfs allowlist) and does not claim a live trappserv.er result.

Read-only scope audit: module imports only node:fs/promises stat/statfs and path.isAbsolute; its returned surface is getSources/read. There are no write, configuration, mount, process-execution, environment, API, or host-enumeration operations. Review status remains In Progress for Root.

Root review correction evidence (2026-11-04): Removed Btrfs (0x9123683e) from the accepted filesystem types and added a direct regression that its statfs magic returns unavailable. The official Btrfs subvolume docs say subvolumes can be separately mounted and share the whole filesystem's single storage pool (https://btrfs.readthedocs.io/en/latest/Subvolumes.html, lines 7-24); Linux kernel proc docs describe mountinfo's major:minor as `st_dev` (https://docs.kernel.org/filesystems/proc.html#proc-pid-mountinfo-information-about-mounts). This confirms the accounting risk for this adapter's `st_dev`-only identity; no new filesystem identity mechanism was added. ext and xfs remain allowlisted.

Re-reviewed concurrent reads: same-scope requests share the in-flight sample and each caller receives a deep-enough clone of the reading/filesystem records; last-good entries are keyed by scope, so stale results remain coherent for that scope. No correctness defect or code change was needed in the in-flight/stale logic.

Post-correction verification: `npx vitest run src/server/disk-capacity.test.ts` passed 16/16; `npm run typecheck` passed. No Linux host smoke was available; no value from this macOS host is classified as a Linux filesystem.
