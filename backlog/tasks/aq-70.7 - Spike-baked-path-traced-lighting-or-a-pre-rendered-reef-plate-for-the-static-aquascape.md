## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Per user direction (2026-11-05), investigate a hybrid ("mix") rendering pipeline combining offline path-traced lighting for static components with real-time rendering for dynamic elements.

In a hybrid architecture:
- Static structures (bare live-rock island foundations, calcified stony coral skeletons, dead coral bases) leverage offline path tracing in Blender Cycles to achieve physically accurate global illumination, micro-cavity ambient occlusion, multi-emitter soft shadows, and subtle color bleeding.
- Dynamic elements (soft coral fleshy crowns, swaying tentacle meshes, bubble-tip anemone polyps, animated caustic light networks, and swimming fish) remain real-time 3D meshes with dynamic shading and vertex displacement.
- Research the seamless integration of both in Three.js:
  1. Lighting blending: How to combine baked diffuse GI/lightmaps (e.g. via second UV set or baked vertex colors/textures) with real-time directional LED key/fill lights and overhead caustic projection without double-counting light or creating mismatch seams.
  2. Asset pipeline & glTF standards: Feasibility of lightmap textures (KTX2/Basis) or baking into custom glTF extensions/attributes in Blender 5, preserving existing modular socket and contract conventions (AQ-42, AQ-52, AQ-53).
  3. Real-time interaction: Fish casting dynamic shadows onto baked rock surfaces, ambient occlusion when fish swim near rock/caves, and caustic animation washing over baked surfaces.
  4. Dynamic soft corals mounted on static baked rock: Avoiding jarring visual discontinuities at the mounting skirts (e.g. matching ambient light levels, smooth transition masks).
  5. Performance and memory: Compare download size, GPU memory, and shader overhead of lightmapped static geometry vs pure real-time PBR + screen-space effects (GTAO/SSAO).
  6. Compatibility with zoom (AQ-62), hit-test picking (alpha-picking), and habitat collision boundaries (AQ-58).

Deliverable: Research document in docs/ (e.g., docs/hybrid-reef-rendering-research.md) registered in docs/README.md, detailing the technical architecture, recommended toolchain, sample workflow, and next implementation steps.
