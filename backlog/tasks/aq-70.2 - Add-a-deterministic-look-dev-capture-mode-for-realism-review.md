## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Realism iterations need repeatable before/after comparisons. Today fish positions, coral sway and caustic time vary between frames, labels cover parts of the reef, and a previous generic screenshot API produced clipped JPEGs despite .png names (see AQ-63/AQ-66 evidence corrections 9ca488d/5d6fc47). Without a deterministic capture path, look-dev reviews cannot distinguish real improvement from a lucky frame.

Needed capabilities (exact mechanism is the implementer's choice, for example a dev-only query flag plus a Node/Playwright-style script):
- Frozen scene clock at a chosen time, seeded fish placement, and a broadside "hero" pose per visible species so fish skin/fins can be judged.
- Optional label hiding for art review (labels remain on by default in normal use).
- Full-frame captures at exactly 1440x900 and 402x874 CSS pixels, scale 1, true PNG (verify signature and IHDR dimensions).
- At least three close-up camera presets (fish macro, coral macro, rock/sand contact) for material review.
- Renderer statistics alongside every capture: renderer.info (draw calls, triangles, textures, geometries), frame-time percentiles over a fixed window, and total downloaded asset bytes.
- Output under docs/asset-evidence/photorealism/<date-or-task>/ with a JSON manifest (commit, viewport, preset, stats).

Responsive verification uses only 1440x900 (laptop) and 402x874 CSS pixels at scale 1 (iPhone 18 Pro proxy); do not add a broader device matrix.
<!-- SECTION:DESCRIPTION:END -->
