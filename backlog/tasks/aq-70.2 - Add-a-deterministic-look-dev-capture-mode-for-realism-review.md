## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Realism iterations need repeatable before/after comparisons. Today fish positions, coral sway and caustic time vary between frames, labels cover parts of the reef, and a previous generic screenshot API produced clipped JPEGs despite .png names (see AQ-63/AQ-66 evidence corrections 9ca488d/5d6fc47). Without a deterministic capture path, look-dev reviews cannot distinguish real improvement from a lucky frame.

Needed capabilities (exact mechanism is the implementer's choice, for example a dev-only query flag plus a Node/Playwright-style script):
- Frozen scene clock at a chosen time, seeded fish placement, and a broadside "hero" pose per visible species so fish skin/fins can be judged.
- Optional label hiding for art review (labels remain on by default in normal use).
- Full-frame captures at exactly 1440x900 and 402x874 CSS pixels, scale 1, true PNG (verify signature and IHDR dimensions).
- At least three close-up camera presets (fish macro, coral macro, rock/sand contact) for material review.
- Renderer statistics alongside every capture: renderer.info (draw calls, triangles, textures, geometries), frame-time percentiles over a fixed window, and total downloaded asset bytes.
- Output under docs/asset-evidence/photorealism/<date-or-task>/ with a JSON manifest (commit, viewport, preset, stats).

Responsive verification uses only 1440x900 (laptop) and 402x874 CSS pixels at scale 1 (iPhone 18 Pro proxy); do not add a broader device matrix.

## Bounded implementation plan (AQ-70.2)

### Current constraints and findings
- The active renderer is the main Three.js scene in `src/rendering/scene/aquarium.ts`; it owns camera, animation loop, coral/shader time, fish pose, renderer, and asset loads. The canvas is a full-viewport layer with separate DOM service-label overlay.
- Scene time is already centralized as `coralElapsedSec`; fish and clip advancement occurs in `render(steps)`. Existing seeded defaults are identity-deterministic, but look-dev needs an explicit seed/time/preset override and a non-advancing frame path.
- Main DPR is capped at 1.5. Root's screenshot preflight found reproducible native PNGs only with CDP `Page.captureScreenshot({format:'png', fromSurface:true, captureBeyondViewport:false})` and no explicit clip; the variant with captureBeyondViewport/clip returned blank. Root owns all CUA/CDP/browser capture actions. No canvas export or label rasterizer.
- `renderer.info` is available in scene; frame interval samples can describe browser-host RAF intervals, not GPU time. Page Resource Timing can provide encoded byte counts after assets settle; the manifest must name its measurement scope/units.
- `aquarium.ts` is currently shared with AQ-70.12 sand work. Do not edit it until the sand agent hands off the exact source lines.

### Proposed architecture (pending Root review before code)
1. Add a small, pure `src/rendering/scene/lookdev.ts` module for strict dev-flag/query parsing, validated config (`timeSeconds`, integer seed, preset, selected fish, labels visibility), macro preset metadata, percentile calculation and typed manifest stats. Keep stable normal defaults separate.
2. Add focused `lookdev.test.ts` coverage for invalid/missing query flags, production-disabled gating, default labels, deterministic seed/time/preset parsing, three macro preset availability, and p50/p95 on fixed sample arrays.
3. After AQ-70.12 releases `aquarium.ts`, integrate only a compile-time `import.meta.env.DEV`-gated URL mode. When no valid look-dev flag exists, controller/render flow and page behavior remain byte-for-byte equivalent at runtime. In look-dev mode, pause simulation advancement; seed new fish target generation from the supplied seed without changing service identity; place each visible fish in a reproducible broadside hero orientation; set every environment/material time uniform to the requested fixed time; apply one named macro camera preset after assets are ready; optionally hide only the DOM name-label spans while keeping links/anchors and ordinary page defaults intact. The integration must expose a dev-only window bridge only while the valid flag is active.
4. The bridge returns readiness, active config, an explicit synchronous frozen render, the latest `renderer.info` render/memory counts, fixed-window RAF interval p50/p95 (host frame intervals, ms; no GPU-time claim), and summed encoded bytes for scene asset responses once all GLBs/textures load. Define the byte scope in the bridge/manifest and keep counting deterministic across repeat captures by including cached encoded bodies, not only transfer-on-network bytes.
5. Root uses CUA to load only 1440x900 and 402x874 CSS viewports at device scale 1, query the dev mode, wait for bridge readiness and metrics, capture via the proven no-clip native PNG path, then verify PNG signature and IHDR dimensions. Produce four presets (full-scene plus fish-macro, coral-macro, rock-sand-contact), each at both viewports: eight PNGs and a JSON sidecar per image under `docs/asset-evidence/photorealism/<task-run>/`. Repeat captures on the same reviewed commit and compare exact pixel/image hashes; if GPU/driver output varies, document the bound and obtain Root approval for the stated pixel/perceptual tolerance before accepting.
6. Record source commit and clean/dirty state, viewport, DPR, seed/time, preset/target, labels state, PNG SHA-256 + dimensions, renderer.info counts, RAF sample count/window/p50/p95, and scene asset-byte scope/value in each manifest. Root owns all browser validation, baseline image review and commit.
